# Arcade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship three real games (Snakes & Ladders: Python Quest, Linked Snake, Loop Runner) whose rules embed verified Python questions, unlocked by Classroom progress with in-app notifications, for the founder to test live.

**Architecture:** Backend `backend/arcade/` (unlock ladder, question pools) + `backend/routes/arcade.py` (catalog, sessions, server-side grading via the existing `games.engine.score_item`). Frontend `frontend/src/arcade/` (shared engine: loop, input, particles, sfx, shell, question card, session hook) + one folder per game, lazy-loaded from the Play page's new Arcade section. Unlock evaluation runs in both lesson-completion writers and on arcade catalog load.

**Tech Stack:** Python 3.11 / FastAPI / SQLite / pytest; React 19, framer-motion, canvas 2D, WebAudio; vitest with `src/games/__tests__/render.js`.

**Spec:** `docs/superpowers/specs/2026-10-27-arcade-design.md`

## Global Constraints

- Founder defaults (2026-10-27 23:37 "Deploy the games for me to test first"): sound on with mute, stage thresholds 1 / 3 / 6 drill-backed lessons, rival present by default; chapters/boards open once unlocked.
- Questions only from topics whose lesson the learner has completed; never from ahead. Pool floor: a board ships only with ≥ 24 choice items; a game session needs ≥ 12 items in the learner's pool, else the catalog marks it `needs_content` with a message naming the next drill-backed lesson.
- Grading server-side with `games.engine.score_item`; XP via `award_xp(conn, user_id, xp, "game", session_id)` under the shared 150/day cap; game score never becomes XP.
- Unlock notifications in-app only (`channels=["in_app"]`), one summary notification for backfill.
- All art drawn in code, all sound synthesised; chunk per game < 120 kB gzipped; reduced motion honoured via `useReducedMotion`; every choice a DOM button; touch targets ≥ 48 px; colour never the only signal.
- Strings via `usePlayT` keys `arcade.*` (English + Tamil written, others fall back).
- Commits carry `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; branch `feat/arcade` in a worktree; CI → VM timer deploys main.

## Review Focus

1. A learner whose completed lessons give a pool smaller than 12 items opens a game: the catalog must say `needs_content` with the next lesson, and `/session/start` must 409, never deal repeats or unlearned topics (Task 3 `test_session_start_rejects_thin_pool`).
2. Bug Hunt items (`line_then_choice`) inside Snakes & Ladders: the card asks line then fix; a partially right answer scores 1 of 3 and the ladder must still count as "wrong" (Task 3 `test_answer_partial_credit_is_wrong_for_the_game`, Task 6 card test).
3. Tab hidden mid-run in Linked Snake / Loop Runner: the loop must pause and resume without a burst of queued ticks killing the player (Task 4 `useGameLoop pauses when hidden`).
4. Daily XP cap already reached by Play: `/session/finish` returns `xp: 0, xp_capped: true` and still records the session and mastery (Task 3 `test_finish_respects_shared_cap`).
5. Double `/session/finish` (retry after timeout): second call returns the stored result, side effects once (Task 3 `test_finish_idempotent`).
