### Failures Detail

**All 21 failures and 28 collection errors share the same root cause:**

> `pyo3_runtime.PanicException: Python API call failed`
> `ModuleNotFoundError: No module named '_cffi_backend'`

The system Python 3.11 ships a Rust-compiled `cryptography` package that conflicts with the pip-installed version. When `auth.py` imports `jose` → `jose.backends.cryptography_backend` → `cryptography`, the Rust extension panics because `_cffi_backend` (a C-API shim) is absent in the pip layer. **This is a QA environment defect, not an application code defect.**

**12 runtime errors** are database connection failures — no PostgreSQL is running in the container, so tests that call `db.connect()` or similar error out.

**Failing test files:**
- `test_access.py` (12 failures — access control logic tests; crypto dep)
- `test_enterprise_tracks.py` (9 failures — enterprise gating tests; crypto dep)
- 28 collection errors across: `test_admin_generate_trending`, `test_auth_security`, `test_challenge_archive`, `test_classroom*`, `test_enterprise_endpoint_idor`, `test_generate_explain`, `test_graph_auth`, `test_install_package_noop`, `test_lesson_loader`, `test_notifications_api`, `test_onboarding_authz`, `test_ondemand_translate_guard`, `test_org_*`, `test_password_hashing`, `test_platform_settings`, `test_playground_*`, `test_self_serve_enrollment`, `test_semantic`, `test_super_admin_authz`, `test_support`, `test_translation_fallback_flag`, `test_tutor_sessions`, `test_voice_auth`

### Fix Recommendation

Pin the `cryptography` package to a cffi-backed wheel in the QA Dockerfile or use a venv:
```
pip install cryptography==42.0.8 cffi --force-reinstall
```
Or add `cffi` to `requirements.txt` explicitly.
